# Решение домашнего задания к занятию «Микросервисы: принципы»
## Задание 1.  
- Сравнительная таблица решений API Gateway:  
  | Название | Описание | Маршрутизация запросов | Проверка аутентификационной информации | Терминация HTTPS |
  | :--- | :--- | :--- | :--- | :--- |
  | Kong | Open-source API Gateway. Существует в двух редакциях, Kong OSS и Kong Enterprise. Устанавливается как отдельный сервис, принимает запросы от клиентов и перенаправляет их в нужные микросервисы. Функционал расширяется плагинами | Высокопроизводительная маршрутизация REST, gRPC, GraphQL и WebSocket трафика | OAuth 2.0, JWT, mTLS аутентификация и авторизация на уровне шлюза | Нативная функция |
  | Tyk Gateway | Open-source API Gateway. Поддерживает авторизацию, лимиты, аналитику и трансформацию запросов. Легкий gateway, с удобной админкой, подходит, если не требуется enterprise-решений | Есть, настраивается через Listen Path и механизм URL Rewriting| API Key, JWT, Basic, OAuth 2.0 / OpenID Connect, mTLS, External Auth через кастомные плагины| Поддерживается, настройка в tyk.conf |
  | Amazon API Gateway | Удобен, если вся инфраструктура на серверах Amazon | HTTP API, REST API, WebSocket API маршрутизация | C помощью Lambda REQUEST Authorizers или AWS Signature Version 4 | Нативная функция |
  | Apigee | Платформа управления API от Google. Подходит для больших компаний, где много внешних и внутренних API | Есть, настройка с помощью xml | Через применение встроенных политик OAuth 2.0 (операция VerifyAccessToken) или ключей API (политика VerifyAPIKey)| В зависимости от модели импользования (внешняя или ingress-архитектура)|
  | Apache Apisix | Динамический, высокопроизводительный API-шлюз с открытым исходным кодом; динамические обновления; мощная система плагинов; поддержка AI | Настройка с помощью правил обработки| JWT, Keycloak, OIDC/OAuth 2.0, OpenID| Нативная функция|
  | KrakenD | Высокопроизводительный API-шлюз с открытым исходным кодом, написанный на языке Gо; Агрегация данных (BFF); Вся логика задается через единый конфигурационный файл; Построен на архитектуре stateless| KrakenD требует строгого объявления каждого пути; настройка конфигурации в json| Используется валидация JWT, OAuth2, Basic Auth или API Keys | Для обработки HTTPS-трафика можно использовать две стратегии: терминацию силами KrakenD или выделенный обратный прокси-сервер перед ним| 
Исодя из возможных требований универсальности и большой поддержке внешних плагинов можно остановиться на решении Kong или KrakenD. При рассмотрении замеров производительности, способов
конфигурирования при  сравнении решений (опубликованы в общем доступе, [ссылка](https://habr.com/ru/companies/ru_mts/articles/716512/)) можно выбрать KrakenD.

 | Название | Описание | Кластеризация | Хранение | Скорость | Форматы | Разделение прав | Простота |  
 | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
 | RabbitMQ | Брокер сообщений, основанный на протоколе AMQP, это открытый протокол передачи сообщений | Есть сложности при горизонтальном масштабировании в кластере | Хранит сообщения в оперативной памяти для быстрой маршрутизации и на диске для надежности| Высокая| JSON, Protobuf, Msgpack, XML, Plain text| Строится на уровнях: пользователях (аутентификация), виртуальных хостах vhosts (логическая изоляция) и политиках доступа| Простое администрирование, удобная админка|
