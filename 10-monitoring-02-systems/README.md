# Решение домашнего задания по теме "Системы мониторинга"
## Основная часть
  - П.1  По принципу мониторинга SRE требуется собирать только требуемые метрики, поэтому в данном случае можно настроить систему мониторинга на сбор метрик CPU LA (мониторинг загрузки ), IOPS (нагрузка на дисковую подсистему, куда скидываются отчеты), FS (для мониторинга свободного места на диске);  
  - П.2  Можно предложить сбор временных рядов по выделенным метрикам (напр. в Zabbix) и затем визуализацию рядов на графиках и дашбордах;
  - П.3  В зависимости от типа приложения, если оно работает по http и опубликовано в интернет, ошибки 400/500 могут отлавливать бесплатные версии сервисов Rollbar, LogRocket и т.п.  
    На имеющихся установленных системах сбора логов (БД ClickHouse + система сбора логов Vector; PLG) потребуется отключить хранение во избежание переполнения подсистемы хранения;    
    Если система сбора логов не использовалась, то потребуется периодически собирать локально на сервере метрики из подсистемы `/proc` и отправлять эвенты при достижении пороговых значений (это поможет избежать ошибок, связанных с производительностью).  
  - П.4  Формула не учитывает значение summ_3xx_requests в числителе дроби, эти ответы дают недостающие 30%.
  - П.5  Push-ситема неприменима в случае, если установка агента не разрешена по различным соображениям (ограничение);
